FIXES

MORE PAGE
- Fixes the bottom-right More page briefly appearing and then disappearing.
- Route changes are now idempotent, so clicking a tab does not cause a second duplicate render from the hash-change event.
- The messaging and civic observers now watch the app view instead of the entire document, reducing UI races.
- A short More-page stability guard restores the More page if another script unexpectedly overwrites it immediately after the tap.

TOP-RIGHT PROFILE PHOTO
- Citizens with an uploaded profile photo now keep that photo in the top-right account circle.
- The photo is rendered as a persistent CSS background image, so older account code writing an initial such as W or B cannot erase it.
- Citizens without a photo still see their account initial.

BLOCKING
- A Block / Unblock button appears on other citizen profiles.
- A Block / Unblock control also appears inside a direct-message conversation.
- More now includes a Blocked Citizens manager where a citizen can unblock accounts.
- When Citizen A blocks Citizen B:
  * B cannot retrieve A's citizen profile.
  * B cannot retrieve A's posts in the authenticated feed.
  * A and B cannot exchange new direct messages in either direction.
  * New follows between them are prevented.
- The blocker can still view the blocked citizen's profile so the block can be managed/reversed.
- Blocking is enforced in Supabase RLS/triggers, not only in JavaScript.
- Anonymous users have no access to the block table.

DIRECT MESSAGE SAFETY FILTER
- Direct messages are checked in the browser for common prohibited language before submission.
- Supabase independently checks every inserted DM server-side.
- The server blocks configured racial/identity slurs, common profanity/vulgar terms, and explicit threatening phrases/patterns.
- Users receive a generic message asking them to remove profanity, slurs, vulgar, hateful, sexual, offensive, or threatening language.
- The server-side rule cannot be bypassed by editing the browser JavaScript.
- This is a rules-based safety filter. No static filter can identify every offensive expression or every evasive spelling, so it should be treated as one moderation layer rather than a guarantee that all harmful content will be caught.
